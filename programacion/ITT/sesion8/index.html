Un vector: elementos agrupados

Una estructura de datos · todos del mismo tipo · un solo nombre

Las posiciones empiezan en 0

Un vector agrupa una colección de elementos, todos del mismo tipo, bajo un único nombre. Este es el del guion: v, 10 elementos de tipo int.
A cada elemento se accede por su posición: v[0], v[1], v[2]…
El primero siempre es el 0, así que con 10 elementos el último es v[9]. v[10] no existe, y el compilador normalmente no avisa. Luego vemos por qué.

El tamaño va en una constante, MAX, y typedef define un tipo nuevo: TipoVector es un vector de MAX celdas de tipo int. Así está en lib_vector.h.
Esto no crea ninguna variable: es el molde.
Con el molde se definen las variables y los parámetros que queramos. Recién definidos no sabemos qué contienen: por eso las interrogaciones.

Con cada celda podemos hacer lo mismo que con un int. Asignar: v[0] pasa de 5 a 7.
Leer de teclado: el usuario escribe 12 y se guarda en v[3].
Escribir por pantalla: sale el valor de v[7], un 50.
Usar celdas en una condición: la primera parte es falsa, así que el if no se cumple.
Y lo más importante: el índice puede ser una variable. v[i] con i = 4 es v[4]. Eso es lo que nos permite recorrer un vector con un bucle.

Tentación: copiar un vector en otro con una asignación. No compila; este es el mensaje real de g++.
Con un int funciona porque es un dato simple. Un vector es una estructura: no hay asignación del vector completo.
El guion dice que ninguna es correcta, y es así. Pero hay un matiz: las dos últimas compilan, y no hacen lo que parece. Comprobado con g++ 9.4 y las opciones por defecto, sin ningún aviso: cout imprime la dirección de memoria, y v == w dio «distintos» con dos vectores de idéntico contenido. Es peor que un error de compilación, porque no os enteráis.
La solución: módulos que recorren el vector y operan celda a celda, y que se comportan como esas operaciones. Los nombres son un ejemplo; varios ya los tenéis en lib_vector. La idea es que, para trabajar con un vector completo, hay que iterar. Ojo con el orden en copiar: copia el primero en el segundo, así que v = w sería copiar(w, v).

Por dentro: una dirección y celdas consecutivas

v → 0x7fffddbc1190
sizeof(int) = 4 bytes
+20 bytes +40 bytes
?

v[10]fuera del vector

10 celdas × 4 bytes = 40 bytes seguidos

v[5] → v + 5 × sizeof(int) → v + 20

v[10] → v + 10 × sizeof(int) → v + 40

C++ no comprueba los límites: va a esa dirección, haya lo que haya

Esa dirección es la que imprimía cout << v: un vector es, en el fondo, la dirección de su primera celda. A partir de ahí hay MAX elementos seguidos, cada uno de sizeof(tipo) bytes. Con int, 4 bytes: 40 en total.
Por eso se empieza en 0: el índice es un desplazamiento. v[5] va a la dirección de v y avanza 5 veces el tamaño del tipo, 20 bytes.
v[10] hace la misma cuenta y cae justo después de la última celda. Nadie lo comprueba: es comportamiento indefinido. Puede no pasar nada visible, machacar otra variable, abortar o dar un segmentation fault. Probado con g++ y v[10] = 99: el programa siguió y, al terminar, abortó con «stack smashing detected». Típico: i <= MAX en el for.

Recorrer un vector: un for de 0 a MAX-1

void iniciarAleatorio ( TipoVector &v, int maxValor ) {
    int i; // índice de 0 a MAX-1
    for ( i = 0; i < MAX; i++ ) {
        v[i] = rand() % ( maxValor + 1 ); // valores en [0, maxValor]
    }
}
i
iniciarAleatorio(v, 9);

Valores de ejemplo

Este módulo ya lo tenéis hecho en lib_vector.cpp. Es el esquema de casi todo lo que vais a implementar hoy: un for con i desde 0 hasta MAX-1, y en el cuerpo se trabaja con v[i]. El comentario de la i es su rol: indicadlo en todas las variables. El parámetro va por referencia, con &, porque el módulo modifica el vector.
Animación: i recorre las posiciones y cada celda recibe un valor en [0, 9], que es lo que da rand() % 10. Al final, cuando i llega a 10, i < MAX es falso y el bucle acaba, sin tocar v[10]. Se usa sobre todo para agilizar las pruebas.
